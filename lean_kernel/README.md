# Kernel-only Lean proof of K₂ ≥ 0.301657

This directory contains a second proof in Lean 4, of the weaker bound K₂ ≥ 0.301657, under the same hypothesis as the
proof of K₂ ≥ 0.301665 in `../lean/` (the inequality A₃ + B₂²/2 ≤ 2, Lemma 3.4 of the paper). It uses the certificates
for S₅ ≤ 2.187 and S₆ ≤ 2.363 and Newman's bound S_n ≤ √n in the degrees n ≥ 7, but not the certificate for S₇. Every
check runs in the Lean kernel: the proof does not use `native_decide`, so its trusted base is Lean's kernel, including
the kernel's built-in arithmetic on natural numbers. Section 7 of the paper describes it.

The main theorem is in `Bohr59aK6G/Final.lean`, one of the generated files described below:

    theorem Bohr59aK.K2_ge_K (hPC : PatelColligation) : K2Claim

Here `K2Claim` is `(301657 / 1000000 : ℝ) ≤ K2`. `K2Claim`, `K2` and `PatelColligation` are the definitions of
`../lean/`; the files `Bohr59a/Statement.lean` and `Bohr59a/Hypotheses.lean` are the same in both directories. The same
file also proves the bound for S₆ on its own, as `Bohr59aK.sidon6K : SidonBound 6 (2363 / 1000)`.

## Axioms

`lake env lean AxK6.lean` prints the statements of these two theorems and the axioms of four theorems, the main theorem
among them; `AXIOMS.txt` is the expected output. The axioms are only the three standard axioms `propext`,
`Classical.choice` and `Quot.sound`.

## How the proof works

- `Bohr59aCoreK/` is a checking program in core Lean that uses only integers and structural recursion, so that the
  kernel can evaluate it. `Vertex.lean` checks one vertex certificate. Besides the entries of the vector y in the vertex
  certificate, the check uses a unit lower triangular matrix W and a vector x, which it computes in fixed-point
  arithmetic; any values would do, since the inequalities themselves are checked exactly. `VertexH.lean` is the same
  check with W and x given as data, and `Packed.lean` decodes the entries of y, W and x of a vertex certificate from a
  single natural number. The proof for S₅ uses `Vertex.lean`, the proof for S₆ `Packed.lean`. `Walk.lean` and
  `Walk2.lean` check that the boxes of a cell of the initial grid use exactly given lists of vertex keys, and
  `AllP.lean` has a lemma used to join the chunk theorems described below. `TrigTab.lean` is a table of balls for the
  cosines and sines of the vertex phases. It was generated by a short Lean script that is not included, and
  `TrigOK.lean` checks each entry in the kernel against the ball arithmetic of `C64Core/Ival.lean`, so the script need
  not be trusted.
- `Bohr59a/CertK.lean` proves this checking program correct. With `Bohr59a/CertGeom.lean` and `Bohr59a/CertShard.lean`
  it turns checked cells into bounds for S₅ and S₆, and `Bohr59a/FinalV3.lean` derives K₂ ≥ 0.301657 from the hypothesis
  and these two bounds.
- The generated modules hold the certificates. For S₆, the 32,768 cells of the initial grid are divided into 45 ranges
  of consecutive cells. For each range, `Bohr59aK6V/` has one theorem, proved by `decide +kernel`, for each distinct
  vertex of the boxes in the range; a vertex shared by two ranges is checked in both, which gives 5,633,890 theorems in
  5,657 modules. `Bohr59aK6C/` splits the vertex keys of each box into chunks of at most 81 keys, with a theorem for
  each chunk that gives every key of the chunk its vertex theorem (3,845 modules). Its other 512 modules hold, for each
  cell, the tree of its boxes, the keys of each box and a theorem, proved by `decide +kernel`, that the walk over the
  boxes of the cell uses exactly these keys. The 512 glue modules in `Bohr59aK6G/` combine the cells into
  `SidonBound 6 (2363 / 1000)`, and `Bohr59aK6G/Final.lean` proves the main theorem.
- For S₅ the modules are those of version 2 of this proof: `Bohr59aK5V/` has a theorem for each of the 269,769 vertex
  certificates, `Bohr59aK5C/` the walk theorems of the 4096 cells and the theorems that give each key its vertex
  theorem, and `Bohr59aK5G/Final.lean` proves `Bohr59aK.sidon5K : SidonBound 5 (2187 / 1000)`. That file also contains
  the theorem of version 2, K₂ ≥ 0.301633, which `Bohr59a/FinalV2b.lean` derives from the hypothesis, the bound for S₅
  and Newman's bound in the degrees n ≥ 6.
- The certificate gives the entries of y as floating-point numbers. The generator for S₆ writes each entry as an integer
  multiple of 2⁻¹²⁸; in two vertex certificates some entries are not of this form and are rounded, by at most 1.5·10⁻³⁹.
  The kernel checks the inequalities exactly for the values it is given, so the rounding needs no further argument.

Except for `Bohr59a/CertK.lean` and `Bohr59a/FinalV2b.lean`, the files under `Bohr59a/`, `Bohr59aCore/`, `C64Core/` and
`C64/` are the same as in `../lean/`; this proof uses only part of them.

## Files

- `Bohr59a/`, `Bohr59aCore/`, `C64Core/`, `C64/`, `Bohr59aCoreK/`: the sources described above.
- `KHints.lean` and `Bohr59aCoreK/Hints.lean`: the program `k6hints`, which computes W and x for the generator. It is
  not part of the proof.
- `tools/`: `gen_k5.py` writes `Bohr59aK5V/`, `Bohr59aK5C/` and `stats/K5K.json` from the certificate for S₅, and
  `gen_k5_final.py` writes `Bohr59aK5G/`. `gen_k6.py` writes `Bohr59aK6V/`, `Bohr59aK6C/` and the files
  `stats/K6K_<tag>.json` from the certificate for S₆, and `gen_k6_final.py` writes `Bohr59aK6G/`.
- `stats/`: for S₅, the counts of the generated modules with the checksum of the certificate (`K5K.json`) and the time,
  memory and checksums of each module in the reference build (`K5V_RUN.txt`, `K5C_RUN.txt`, `K5G_RUN.txt`); for S₆, one
  file `K6K_<tag>.json` for each range, with its cells, the counts of its modules and the checksums of the 48 files of
  the certificate.
- `generated_SHA256SUMS`: the SHA-256 checksums of the 11,109 generated modules and of the 46 files in `stats/` that the
  generators rewrite.
- `AxK6.lean`, `AXIOMS.txt`: the axiom query and its expected output.
- `lakefile.toml`, `lake-manifest.json`, `lean-toolchain`: the project configuration.

The generated modules are not included.

## Generating the modules

As with `../lean/`, install `elan`; `lean-toolchain` and `lake-manifest.json` select Lean `v4.35.0-rc3` and Mathlib
commit `c55e6e786f49471c72fbddbec5415808896aec1e`. Unpack the 48 files of the certificate for S₆ into
`../certificate/s6_certificate/`, as described in `../README.md`. Then, in this directory, run

    lake exe cache get
    mkdir -p v3
    ln -s "$(cd ../certificate && pwd)/s5_certificate.json" v3/bb5_t2187.json
    ln -s "$(cd ../certificate && pwd)/s6_certificate" v3/bb6
    python3 -I -B tools/gen_k5.py v3 .
    python3 -I -B tools/gen_k5_final.py . 1
    lake build k6hints
    R=$(python3 -I -B -c 'import glob, json; s = sorted((json.load(open(p)) for p in glob.glob("stats/K6K_*.json")), key=lambda d: d["first_cell"]); print(",".join("%d:%d:%s" % (d["first_cell"], d["ncells"], d["tag"]) for d in s))')
    python3 -I -B tools/gen_k6.py v3 . .lake/build/bin/k6hints 8 1000 64 "$R" pack
    python3 -I -B tools/gen_k6_final.py .
    rm -r tmp_hints_*
    sha256sum -c generated_SHA256SUMS

The generators read the file names `bb5_t2187.json` and `bb6/sh0.json`, ..., `bb6/sh47.json`, hence the links. The line
that sets `R` lists the 45 ranges from the files in `stats/`. The fourth argument of `gen_k6.py` is the number of
processes. With 60 processes it took about 17 minutes, and its largest process used about 12 GB of memory; the
generators for S₅ and `gen_k6_final.py` take seconds. Neither the generators nor `k6hints` need be trusted: the walk
theorems force the key list of each box to be exactly its vertex keys, each key carries its own kernel-checked vertex
theorem, and the kernel checks every vertex certificate with the W and x it is given.

## Building

Run

    lake build Bohr59aK6G.Final
    lake env lean AxK6.lean

Plain `lake build` does not work here: its default target needs the file `Bohr59a.lean`, which is not part of the proof
and not included. The output of the last command should agree with `AXIOMS.txt`.

The build is long. The reference build ran on many machines. Each of the 5,657 vertex modules for S₆ took about 237
seconds on an otherwise idle machine and about 405 seconds with 64 of them running in parallel, and used about 0.65 GB
of memory. The chunk modules took 8 to 30 seconds each and the cell modules between 6 and 650 seconds. The 512 glue
modules took about 10 seconds and 6.6 GB each, and `Bohr59aK6G/Final.lean`, which imports every module, took 39 seconds
and 38 GB. In all, the modules for S₆ took about 620 CPU-hours, and those for S₅ about 45 more (`stats/K5*_RUN.txt`).
